# CRM «Детроид»

Однофайловая канбан-CRM для ведения лидов: воронка из 6 стадий, карточка клиента,
лог-«чаттер» с вложениями. Чистый HTML/CSS/JS — без сборки, фреймворков и сервера.

## Запуск

Просто откройте `crm.html` в браузере.

## Возможности

- Канбан с воронкой из 6 стадий и перетаскиванием карточек; каждая смена стадии пишется в лог карточки.
- Стадии «вне воронки» (из старых версий данных) показываются отдельной помеченной ⚠️ колонкой и не теряются.
- Карточка лида: автосохранение полей, подсказки валидации (ИНН — 10 или 12 цифр, формат email),
  счётчик заявок, удаление карточки.
- Лог-«чаттер»: комментарии (Enter — отправить, Shift+Enter — перенос строки),
  инлайн-редактирование и удаление, вложения файлов с превью изображений и скачиванием.
  При редактировании комментария исходное время создания сохраняется, добавляется пометка «изм.».
- Экспорт/импорт всех данных вместе с вложениями в один JSON-файл (кнопки на панели списка лидов) —
  используйте «Экспорт» как резервную копию.

## Данные и хранилище

- Лиды и комментарии хранятся в `localStorage` (ключ `crm_leads_v9`).
  Данные из предыдущей версии `crm_leads_v8` переносятся автоматически; старый ключ
  остаётся на месте как резервная копия.
- Вложения хранятся в `IndexedDB` (практически без ограничения размера).
  Если браузер не предоставляет IndexedDB, включается резервный режим хранения вложений
  в `localStorage` — приложение предупредит о лимите ~5 МБ.
- Повреждённые данные не затираются: битая копия сохраняется в ключе
  `..._corrupted_<ts>`, приложение стартует с демо-данными и показывает уведомление.
- Все идентификаторы — строки (криптостойкие UUID), всё пользовательское содержимое
  экранируется при выводе (защита от XSS).

## Тесты

```
npm install
npm test
```

Смоук-тесты (`tests/smoke.test.js`, запускаются в jsdom) покрывают:
защиту от XSS в канбане и логе, валидацию модалки и формы, миграцию с `crm_leads_v8`,
колонку для неизвестных стадий, поведение при повреждённом хранилище, экспорт/импорт
и полный цикл вложений в IndexedDB (миграция старых файлов, запись новых, чтение после
«перезагрузки», очистка при удалении).
